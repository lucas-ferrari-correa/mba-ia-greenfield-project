# GET /videos/:publicId/stream and GET /videos/:publicId/download Test Plan

## Application Overview

Public delivery endpoints. Both answer only for `ready` videos and respond `302` to a presigned `GetObject` URL, so playback and download go straight to object storage: storage serves `Range` requests with `206 Partial Content` (streaming without a full download), and the download URL forces `Content-Disposition: attachment` with the original file name. Any other status, unknown id or malformed id returns `404` to everyone, owner included.

## Test Scenarios

### 1. Streaming

**Setup:** `beforeEach` cleans the test DB and clears `ThrottlerStorageService.storage`; app bootstrapped from `AppModule` with `main.ts` globals; env overrides: `S3_PUBLIC_ENDPOINT=http://minio:9000`, `VIDEO_UPLOAD_PART_SIZE_BYTES=5242880`, `QUEUE_PREFIX=test-<random>`. Fixture: a video uploaded for real (draft → parts → complete) with the MP4 generated by `test/fixtures/generate-video-fixtures.ts`, then its `status` set to `'ready'` directly in the DB (no dependency on the worker). Requests use supertest with redirects disabled; the `Location` is fetched with `fetch`.
